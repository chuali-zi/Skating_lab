# 花滑教练的专业知识、检索和证据

本次实现对应 2026/27 赛季 ISU 成年女子单人自由滑的跳跃规则、五项训练研究或发展框架，以及运动员自己授权使用的知识和记忆。以下说明可以和 Android「资料 → 问滑冰教练」及「准备 → 选择比赛组别 → 生成编排」对照阅读。

## 一个具体问题怎样得到答案

运动员问「3T< 的基础分是多少？」。系统先确认当前选择的赛季、项目、级别、组别和节目，然后把全角字符标准化，保留代号后面的符号。在这个范围内，3T< 对应 R3 分值表第 3 页的一行，BASE 是 **3.36**。查询返回数值、适用条件、带页码的 PDF 链接和引用标识。从同一行误取 GOE 对应的分数会改变结果，所以逐行校验对照的是 BASE 列。[ISU 分值表，第 3 页](https://isu-d8g8b4b7ece7aphs.a03.azurefd.net/isudamcontainer/CMS/Corporate-Site/Governance/Transparency/ISU-Communications/2786-SinglesPairs-SOV-Update-260602-1780481099-6311.pdf#page=3)

「连跳里步出，紧接着跳的下一跳还算分吗？」涉及一条有条件的程序规则。检索同时寻找连跳或连续跳、摔倒或步出、紧接着的后续跳和计值意图。对应 R2 第 33 页，同组内这些后续跳标星、不计值。若描述写明前一组已经结束、后面开始一个独立元素，资料中的这条解释无法回答新问题，系统会返回资料不足。[ISU 技术组手册，第 33 页](https://isu-d8g8b4b7ece7aphs.a03.azurefd.net/isudamcontainer/CMS/Corporate-Site/Sports-Rules/Figure-Skating-Rules/Handbooks-Single-%26-Pair-Skating/TP-HandbookSingles-26-27-15-July-2026-1784641784-3364.pdf#page=33)

「同名三周、四周、五周分别算几种？」在该资料包中存在同一适用范围的来源差异。系统保留 R1 第 71 页、R2 第 27 页、R3 第 14 页的定位，回答栏留空。两份材料意见相同也不能替第三份消除冲突。复核接口支持显式限定来源，答复仅代表选中的材料。这个行为有独立的回归用例。[规则原文](https://isu-d8g8b4b7ece7aphs.a03.azurefd.net/isudamcontainer/CMS/Corporate-Site/Governance/Isu-Regulations/2026-FS---Pair-Sports-Rules-FINAL-20260513-1778685370-9916.pdf#page=71)

## 检索设计和研究依据

**结构化定位。** 动作代号、技术标记、条款号和已核分值走精确查找。3T、3Tq、3T<、3T<< 可能相邻，简单删除标点或只计算字面相似度都会产生错误。五周跳进入组合的提问还必须先处理组合政策。单跳的基础分无法回答组合资格。对于普通跳跃，中文跳名也能转换为项目使用的规范代号。

**中文专业检索。** 规则和训练摘要先按问题与适用条件筛候选，再由固定版本 BGE 中文模型在本地 CPU 上计算相似度。问题带检索前缀，资料带适用条件，取首个 token 的表示并归一化。当前使用 512 维向量和 256 token 的输入上限。公开说明的向量按不可变条目缓存。最优主题相似度至少 0.52，与下一个主题至少相差 0.04；这是继承后在本项目小样本回归中验证的阈值，不是动作准确率。入选某项主张后会拉回该项全部适用来源再查冲突，排名低的矛盾材料也能被保留。缺模型时，充分且唯一的已审主题仍可回答；语义相邻的多个候选将要求更多证据。[BGE 模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5) · [ONNX Runtime Java](https://onnxruntime.ai/docs/get-started/with-java.html)

**私人资料的混合检索。** 应用在 PostgreSQL 的当前租户事务内，分别查询全文索引和 pgvector 余弦距离，仅比较相同模型及维度。两份排名用 RRF 合并，即每份排名的第 r 项贡献 1/(60+r)，再从当前有效原文取回证据。模型切换后，后台逐批处理旧索引。推荐默认取前 10 项，对前三项展开同一来源的相邻块，再补入当前比赛资料；超过上下文上限的段落数会告知模型。完整文档仍可按页打开。公开知识、比赛私有材料和个人状态能共同参与推荐，各自的证据身份与撤回机制独立。[RRF 原论文](https://dl.acm.org/doi/10.1145/1571941.1572114) · [pgvector 官方实现](https://github.com/pgvector/pgvector)

**为什么给模型看有限且可查证的原文。** RAG 研究把外部文档和生成推理连接起来。BEIR 展示了不同数据集合上检索器的差异，项目需要用本域问题检验。Lost in the Middle 展示了相关信息在长上下文中所处位置会影响模型利用它的表现。因此同一请求中只展开必要正文，发送一份证据索引，保留找不到材料、跨范围、同题矛盾等结果。通用模型仅负责组织和比较可执行建议，服务器核对候选动作、已完成前缀、引用 ID 并复算可表示的数值。当前模板要求有专业材料时每个候选至少引用一项专业证据，选择视频时还要引用特定复核版本；这能验证来源存在，仍须抽查文字是否忠实使用来源。[Lewis 等的 RAG 论文](https://arxiv.org/abs/2005.11401) · [BEIR](https://arxiv.org/abs/2104.08663) · [Lost in the Middle](https://arxiv.org/abs/2307.03172)

## 训练科学知识可以支持的判断

| 来源 | 研究对象和观测方法 | 教练能据此说什么 |
| --- | --- | --- |
| [Yamaguchi、Sakurai，六种双周跳](https://doi.org/10.3389/fspor.2025.1597598) | 7 名高水平女性选手，比较六种双周跳的起跳角动量 | 可以解释不同跳种中手臂和自由腿贡献的差异，复盘时应对齐跳种和动作阶段 |
| [青少年 Axel 生物力学研究](https://doi.org/10.3389/fbioe.2025.1606817) | 11 名青少年参与，只有 3 人也完成双周 Axel；研究使用双机位高速录像及肌电 | 可以讨论不同周数的学习与研究条件，不能凭这份研究推算某个人多少天能升周 |
| [Lockwood 等，落冰观测](https://pubmed.ncbi.nlm.nih.gov/16939155/) | 10 位全国排名选手，三维录像和 42 位裁判评价 | 可以解释姿态评估所需证据，以及稀疏抽帧能看到什么；不足以判该次精确落冰时间或 GOE |
| [双人滑选手重复跳跃研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC3737852/) | 36 名双人滑选手，60 秒陆上重复跳跃测试 | 可询问本人疲劳感与历史尝试；陆上指标无法直接给出某位冰上选手第几秒开始疲劳 |
| [Skate Canada 长期发展](https://skatecanada.ca/community/athletes/long-term-development/) | 协会发布的培养框架 | 用于区分技能阶段、近期任务和长期目标，结合本人训练记录讨论进阶 |

## 验收口径

23 道带预期出处的问题覆盖精确分值、组合与重复、技术标记、动作阶段和训练研究。每题要求前三条以内出现目标条目，证据 ID 能对应回答，定位匹配预期的 PDF 页或研究章节。MRR@3 计算首个正确条目名次倒数的平均值，无命中记零。

| 在相同题目上比较 | 前三条命中且出处正确 | MRR@3 | 实际交给 BGE 排序的题 |
| --- | ---: | ---: | ---: |
| 结构化和经审主题，关闭向量模型 | 22 / 23 | 0.935 | 0 |
| 结构化、主题筛选加真实本地 BGE | 23 / 23 | 0.978 | 18 |

关闭向量的那一题谈到青少年 Axel 进阶，同时覆盖一般发展阶段和具体的 Axel 研究。保守分支给出歧义提示。启用 BGE 后命中研究人群和方法对应的来源。另测错误组别、未知分值、超出范围的新元素、无关问题、互相冲突的资料、过期版本和来源筛选；对 165 行基础分逐项检查了值及页码。题目和知识库共同维护，这些数字衡量本版本的回归表现。没有独立裁判／教练盲标的跨赛季题库，也没有运动员长期训练结果数据。检索命中、模型说明正确、真人教练认可和实际上冰效果是四项不同的测量。[评测用例](../server/src/test/java/com/skatingcoach/knowledge/ExpertRetrievalTest.java) · [RAGAS 对检索与回答质量的区分](https://aclanthology.org/2024.eacl-demo.16/)

### 与一场真实比赛的裁判表核对

另外选择了**未编入 Java 规则包**的 2026 Skate Canada International 成年女单自由滑裁判明细，共六页。本场于 11 月 1 日举行，处于所选规则包有效期内。先核对原表的 Executed Elements、Base Value、GOE、加成 x 分列，再从六页提取全部独立单跳行。用实际专家 HTTP 接口逐个询问代号的基础分，同时要求有可打开的 PDF 页码。48 行共有 20 种不同代号，含欠周、不清刃及组合技术标记。28 行直接对照表值，另外 20 行只在裁判表已经给出 x 时乘以 1.10。**48/48 与裁判表的 Base Value 一致。** 例如第 1 页的 3A 为 8.00，4T< 为 7.60。这个核对不将旋转、步法、连跳、GOE、节目内容分纳入分母，也没有测试系统能否独立确定后半程加成归属。规则包和比赛打分表的 SHA-256 分开固定；比赛表 SHA-256 为 0d475f51aaff8001213cb44bac462db41d936f513bac1cc11aa8fc89e44345a1。[ISU 官方裁判明细](https://www.isuresults.com/results/season2627/gpcan2026/FSKWSINGLES-----------FNL-000100--_JudgesDetailsperSkater.pdf) · [按 PDF 复跑的脚本](../scripts/verify-official-protocol.ps1)

## 计分与视频的边界

在空白的独立开发库另做了一次真实 GLM-5.3 建议。虚构选手说后半程容易疲劳，愿把较有把握的 2T 放在后面，要求各用一次 2A、2T。服务给出「2A → 2T」和「2T → 2A」两个不同顺序，一次即通过来源与动作校验。候选关联到本人的自述和反复跳跃研究，保留了疲劳尚无个人实测的数据缺口。服务器分别复算出两套的表内基础分之和均为 4.60，确定赛事总分留空。这个例子验证了个人情况、真实检索、生成、引用和计分在同一次产品请求里连通。

三段公开比赛录像经过同一套视频入口。逐帧对照记录了一个明确的主体误判和一处手臂描述证据不足。[逐段实拍验收](public-skating-validation.md)

另外将 Deniss 蹲转录像里可见的屈膝写成人工纠正备注，在开发选手的主方案中冻结第 15 秒已完成的 2T，并要求剩余只安排一个 2A。真实 GLM 经一次修复后通过校验。保存的预案保留了已经完成的 2T、原时间和指定视频的复核版本；模型说明拍摄对象是另一位选手，引用范围限于该段录像。也在 Android API 36 模拟器中从已选主方案打开录像、带入人工复核、建立并保存失误预案，再通过服务端读回核实复核版本和已完成的前缀。手机端另实测了规则原文第 3 页的入口、受身份保护的证据帧及人工纠正保存。[手机问答与复核验收脚本](../tools/mobile-testing/expert.mjs)

选择对应赛季后，编排能使用已核动作表回显各动作的原始基础分、逐行原始合计，以及已表示的数量限制。特定规则包的五周同名冲突、实际技术判定、重复处理、节目中断、后半程起算、组合例外等会影响真正的计值。通用编排器只对它能够表示的规则做确定性运算，覆盖不全时保留待核状态和空的确定总分。用户自己提供的可执行赛事快照保留其原定义。[计算器](../server/src/main/java/com/skatingcoach/scoring/ScoringService.java)

视频模块给出 2–20 张采样图、实际时间及最大间隔。观察须引用 1–4 个递增的有效帧号，技术结论保持待核，可采纳、纠正或忽略。预案只读取主动选择的那一条、那一版备注，修改或撤回后旧引用失效。手机的来源按钮可回看原始证据帧。系统的限制允许如实报出一段录像没有足够可见证据。[视频实现](../server/src/main/java/com/skatingcoach/video) · [视频迁移对照](../archive/fastapi/README.md)
