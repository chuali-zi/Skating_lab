# GLM 真实模型联调记录 · 2026-11-15

本次使用 Windows 已有的 `GLM_API_KEY`，通过 Java 服务实际调用 GLM Coding Plan。输入为合成开发选手资料，不是运动员实测数据。云端返回的候选经过服务端引用、动作选择与冻结前缀检查，再交给 Android。

## 接入方式

- 模型：`glm-5.3`；实际响应返回相同模型标识。
- 开启供应商 `response_format: {"type":"json_object"}`，显式设置 `max_tokens=32768`。推理强度未改动，单次 HTTP 超时 180 秒。
- 端点：`https://open.bigmodel.cn/api/coding/paas/v4/chat/completions`。
- 密钥实际位于 Windows Machine 环境；脚本依次检查 Process、User、Machine，构建完成后才注入服务进程。未写入 `.env`、源码、报告或 Git，Android 和测试脚本不读取密钥。
- 本轮更新后的验证服务运行于 `127.0.0.1:8085`。已有 8080–8084 实例保留；Android 通过 `adb reverse tcp:8085 tcp:8085` 连接验证实例。
- PostgreSQL/pgvector 使用本机实际数据库。未配置 Embedding 服务，本轮知识检索走关键词路径；不能报告为向量检索实测。

端点依据[官方 Coding Plan 接入文档](https://docs.bigmodel.cn/cn/coding-plan/tool/others)。[套餐 FAQ](https://docs.bigmodel.cn/cn/coding-plan/faq)区分支持的工具环境与自建应用服务，本次开关仅显式用于本机开发联调，生产配置应使用适用的标准 API。模型的文本能力以 [GLM-5.3 文档](https://docs.bigmodel.cn/cn/guide/models/text/glm-5.3)为准；本轮没有接入训练视频理解。

测试脚本会创建独立会话及赛事范围，结束时遗忘本轮个人记录并撤回本轮测试资料；既有开发资料不被删除。合成方案和任务保留在开发数据库中，资料撤回后由生命周期机制失效。

## 发现并修复的问题

1. **模型输出失败后重试缺少具体反馈。** 中间版本的真实失误预案请求两次输出不合格，任务失败。现按 JSON、候选结构、证据 ID、动作/规则及冻结前缀分类，反馈具体修复要求，同时提供被拒绝的旧候选供修改。旧候选标为不可信数据，当前用户请求和选择仍优先。最多修复一次；失败公开固定原因码，不把原始回复写入错误或最终结果。
2. **“只返回剩余动作”与完整预案结构混淆。** 提示明确要求完整动作序列，开头逐行保留已经发生的动作 ID、类型、跳跃顺序和时间。服务端仍严格核对前缀，不能靠放宽检查来让模型通过。
3. **建议措辞超出证据。** 早期真实结果出现“成功率最大化”以及把本人报告称为客观完成记录的表达。提示明确区分自述、观察和推测；目标不等于已掌握能力；缺少观测时不得宣称最优、保证或已验证成功率。语义质量仍需教练评估，提示不能保证彻底消除误判。
4. **Android 等待入口不明显。** 云端分析超过客户端一轮约 30 秒的轮询时，准备页现在提供“查看最近一次分析”，继续读取原任务，不需要重新提交。
5. **编排单位歧义。** 真实请求中的“三组跳跃”一度被解释为三轮训练、每轮三次，共返回九行动作。系统提示补充领域定义：本应用一组跳跃对应一个单跳、连跳或连续跳动作行，不能擅自倍增为训练循环。用户仍用自然语言表达，内部 JSON 和校验不转嫁给用户。
6. **仅靠提示和一次修复仍可能连续无法解析 JSON。** 增加供应商结构化输出模式，保留后端语义检查；配置显式输出额度，并把 `finish_reason=length` 单独识别为截断，拒绝发布不完整结果。相近资料干扰场景的真实 JSON 模式探针返回合法 JSON、两份三行动作候选，约 59.9 秒、5001 输出 token（其中 3813 为推理 token）。早先失败未保留原始供应商终止原因，因此不能断言那两次一定由截断导致。[官方 JSON 模式说明](https://docs.bigmodel.cn/cn/guide/capabilities/struct-output)
7. **动作检查失败缺少足够定位信息。** 一次独立记忆用例的候选连续未通过动作检查，旧错误仅为 `SCORING_VIOLATION`，无法从终态确定具体违反项。现在错误码附上服务端固定检查代码，修复提示也明确三种动作类型的独立选择范围、单跳行基数、时间顺序及行 ID 唯一性。不放宽已选范围来通过测试。

真实调用过程中还出现过 `PROVIDER_UNAVAILABLE`（包括一次约 187 秒后失败的请求），该轮未发布建议；没有据此断言网络问题已经修复。测试执行器改为记录失败后继续独立项目，仍以非零退出码表示失败，避免上游一次故障遮蔽后续测试。中间失败不计作通过，最终回归样本也不能用来推断生产成功率。

另有两处测试断言修正，不属于产品故障：更正资料使旧任务 `STALE` 同样表示停止使用，不应仅接受 `REDACTED`；模型引用并解释忽略恶意指令，不等于执行恶意指令，不能仅凭文字包含测试标记判失败。

## 重跑

```powershell

# 在另一 PowerShell 中运行；两组测试顺序执行，避免同时修改同一开发身份的记忆版本。
```
